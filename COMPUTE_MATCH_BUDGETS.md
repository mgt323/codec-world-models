Treat the §0 three-decimal rates as **exact decimals** for budget arithmetic (not IEEE float intermediates).

**Not a budget rate source:** `obs_codecs/diagnostics_comparison_ABCD.json` is **parity-sample diagnostics** (n = 500 shared fixture; labeled in-file). Same tokenizer scheme, different sample — do not feed its averages into compute-matched episode counts.

Definitions used below:

- One **observation** = one timestep string (one encode call).
- Tokens per episode ≈ `avg_tokens_per_observation × n_steps` with `n_steps = 30`.
- **Token-update** = one training token presentation (multi-epoch passes count again).
- Target budget then floored episode counts (see §4):

```text
T_target = 50_000 × n_steps × avg_A
n_episodes(codec) = floor(T_target / (avg(codec) × n_steps))
T_eff(codec) = n_episodes(codec) × avg(codec) × n_steps   # ≤ T_target
```

## 1. COMPUTE-MATCHED regime

**Hold fixed:** nominal token-update target \(T_{\mathrm{target}}\) (proxy for matched FLOPs under identical architecture / optimizer **and** fixed context length \(L\) — see §4). After floor rounding, each codec has its own \(T_{\mathrm{eff}} \le T_{\mathrm{target}}\) (never over budget).  
**Allow to vary:** number of episode presentations per codec (unique world exposure may differ; see §4 locked resampling policy).

### Target \(T\) and floored episode budgets

**\(T_{\mathrm{target}} = 108\,438\,000\)** token-updates  
(= one full pass of Codec **A** over the v0 train split: `50_000 × 30 × 72.292`).

**Rounding (locked):** `n_episodes = floor(T_target / (avg × 30))` so no codec exceeds \(T_{\mathrm{target}}\) even by a fraction of an episode. Report **\(T_{\mathrm{eff}}\)** below as the final per-codec budget configs must hit.

**Rationale:**

- Anchors the longer codec (A) to exactly the info-matched train pool once — no under-use of the generated dataset for A (`T_eff(A) = T_target`).
- Shorter codecs (B/C/D and B E-variants) receive **more** episode presentations than 50k (see table) so they burn nearly the same \(T\) over the same 50k train seeds via the **locked** reshuffle-per-epoch policy in §4 (not a third matching regime and not dataset extension).
- Scale is a plausible **single-seed** stage-1 run for a ~5–20M transformer: at ~50k–150k tokens/s effective, wall-clock is roughly **~12–40 minutes** of training (hardware-dependent). Cheap enough to iterate; large enough that codec gaps are not pure noise before 3–5 seed replications. Scale \(T_{\mathrm{target}}\) by a constant later if pilots underfit — re-apply floor and recompute \(T_{\mathrm{eff}}\) with the same rates.

Alternative pilots (same rates; scale \(T_{\mathrm{target}}\) then floor): dry-run pool `2_000` × A → \(T_{\mathrm{target}} ≈ 4.34\)M; or \(2T\) / \(5T\) for longer single-seed runs.

**Data-loading symmetry (locked with §4):** A/B/C/D and B E-variants must use the **same** reshuffle-per-epoch loader mechanism. (compare v3 token ratios B/A ≈ 0.492 → episode ratios would have been ~2.03× under the same A-anchored target; do not mix eras).

## 4. Decisions before `train/` (locked vs still open)

### Locked

1. **Resampling / repetition (Option a):** Compute-matched "matched" means same total token-updates/gradient budget, not same amount of unique world exposure — B/C/D revisit train seeds within one run via reshuffle-per-epoch (deterministic reshuffle each pass over the same 50k seeds; **within one replication**, the shuffle seed is identical across codecs, which differ only in how many episode presentations that run consumes); draw-with-replacement is explicitly rejected to avoid uneven, independently-random per-codec episode-frequency distributions. Unique-exposure control is the job of the info-matched regime, not compute-matched.

   **Loader identity:** The same reshuffle-per-epoch mechanism applies to **A, B, C, D, and B E-variants**. A’s single non-repeating compute-matched pass still uses that loader (one reshuffled epoch), so codecs differ only in episode-presentation count / epoch count, not in shuffling methodology.

2. **E-variants (B_shuffle / B_reverse / B_bag):** Inherit **B’s exact** `avg_tokens_per_observation`, compute-matched `n_episodes` (**78 770** after floor), and info-matched / compute-matched \(T_{\mathrm{eff}}\) (**68 832 000** info-matched; **108 437 932.8** compute-matched). Rationale: shared B-family vocab / token-preserving (or glyph-swap) surfaces under `regex_v4`; no separate rate row unless a later measurement reopens this.

3. **Sequence construction + FLOPs proxy (fixed context window):**  
   **Locked policy: fixed-length context window** of constant \(L\) identical across A/B/C/D and B E-variants. Training sequences are formed by packing / concatenating / truncating episode token streams into chunks of length \(L\) (with a shared pad id where a chunk is short). **Rejected:** variable-length per-episode sequences (one sequence = natural episode token count, padded only to a per-batch max).

   **Why this is required for the budget’s FLOPs proxy:** under `regex_v4`, mean tokens per episode already differ by ~1.6× (A ≈ 2169 vs B ≈ 1377). Self-attention cost scales \(\propto L^2\) per sequence while MLP cost scales \(\propto L\). If each episode were its own variable-length sequence, matched token-updates would silently give **A more real FLOPs per token-update than B**, breaking compute-matched fairness. With fixed \(L\) for every sequence, attention and MLP costs per token-update are architecture-identical across codecs; therefore **matched token-updates ≈ matched FLOPs** under identical depth/width/optimizer, and a separate quadratic \(\sum L_i^2\) secondary budget is **not** needed for v0.

4. **Document-masked packing (episode isolation within \(L\)) — Option (a):**  
   **Locked:** attention is **blocked across episode boundaries** inside a packed \(L\)-length sequence (document / segment masking). Each token may attend only within its own episode segment (plus the usual causal mask within that segment). **Rejected:** unmasked packing (Option b), where attention spans the full window across concatenated episodes.

   **Why (a):** eval tasks (regime classification, intervention accuracy, next-state) are **per-episode**. Unmasked cross-episode attention would let tokens from one regime / `hidden_c` / intervention setting condition another episode packed into the same window — a confound of the same family this project already rejects elsewhere (no hidden `do()`, information-contract isolation of \(O_t\)). Masking preserves per-episode causal isolation while still using fixed \(L\) for FLOPs parity.

   **Length note (corrects a common misread):** mean episode lengths (A ≈ 2169, B ≈ 1377, C ≈ 1479, D ≈ 1659 tok) are **longer than** \(L \in \{512, 1024\}\) and only fit ≈1 episode (with slack) at \(L = 2048\). So for small \(L\) the packer **splits** long episodes across consecutive windows; for large \(L\) it may **multi-pack** shorter codecs more densely. Either way, a single window can still contain a **boundary** (end of one episode + start of the next, or pad). Document masking applies at every such boundary.

   **Boundary markers:** insert reserved `<bos>` / `<eos>` at **every episode boundary** in the packed stream (visible structure for the model). **Attention-mask derivation must not rely on scanning those tokens alone** — the packer emits a parallel **explicit segment / boundary index array** (episode id or segment id per position); the mask is built from that array (and pad positions). Markers and mask indices must agree; indices are the source of truth for masking.

   **Cross-codec packing density** (episodes per window ≈ \(L / \) avg tok/episode, ignoring small `<bos>`/`<eos>` overhead):

   | \(L\) | A | B (+E) | C | D | Mode |
   |-------|---|--------|---|---|------|
   | 512 | 0.236 | 0.372 | 0.346 | 0.309 | all split |
   | **1024 (locked)** | 0.472 | 0.744 | 0.693 | 0.617 | all split |
   | 2048 | 0.944 | 1.488 | 1.385 | 1.235 | A almost 1; B/C/D multi-pack |
   | 4096 | 1.889 | 2.976 | 2.770 | 2.470 | all multi-pack |

   Density **differs by codec** (expected). Under locked masking **(a)**, that difference affects only **batching / padding efficiency**, not per-episode attention scope or the FLOPs-per-token-update fairness argument (every sequence is still length \(L\) with identical architecture). **If (b) were ever chosen instead**, density differences would become a **live confound** (longer-context mixing for denser codecs) and would need its own fairness argument — do not silently adopt (b).

   **Locked numeric \(L = 1024\)** for v0 pilots (`model/README.md` Decision 1). Rejected 512 (more fragmentation / pad relative to boundary structure at similar split mode) and 2048 (~4× attention FLOPs vs 1024, outside the tens-of-minutes / ~5–20M pilot envelope assumed for \(T_{\mathrm{target}}\)). Under document masking, multi-pack density is **not** required for fairness — fixed \(L\) + segment isolation is.

   **Optimizer-step residual (acceptable, verified — not equalized):** matched \(T_{\mathrm{eff}}\) (token-updates) does **not** guarantee identical optimizer-step counts under packing + fixed `batch_size` — `<bos>`/`<eos>` overhead scales with `n_episodes`, so B/C/D produce a few more \(L\)-windows than A (at \(L=1024\), `batch_size=8`: A 13 250 steps vs B 13 257, ≈0.05%). **Batching policy (observed):** `iter_packed_batches` has **no `drop_last`** — a partial final batch is trained, so steps = \(\lceil n_{\mathrm{windows}} / \mathrm{batch\_size}\rceil\) (confirmed on real Codec A @ bs=8 with `windows % 8 ≠ 0`; a `floor`/drop-last policy would under-consume vs locked \(T_{\mathrm{eff}}\)). Primary matching axis remains token-updates / FLOPs-under-fixed-\(L\); do not retune batch size or pad budgets to equalize steps.

   **Cross-segment loss targets (acceptable, measured — not masked):** the next-token loss scores every non-pad target, including the `<eos> -> <bos>` pair at an episode boundary inside a window (`loss_target_policy = all_non_pad`). Attention is still blocked across that boundary, so this is **not** an information leak — the boundary target is predicted from a hidden state that never saw the other episode. It is a *metric* asymmetry: the density of such targets is set by packing density (A 0.0445%, B 0.0723% of targets), so the residual is codec-dependent. Measured at tier0 `compute_matched` rep0, A vs B (`scripts/measure_loss_mask_residual.py`):

   | Effect | A | B | A−B differential |
   |--------|---|---|------------------|
   | Reporting bias (`loss_all` − `loss_within`) | +0.001286 | +0.000991 | **+0.000295** |
   | Optimization effect (within-segment loss, trained under each policy) | −0.000009 | −0.000170 | **+0.000162** |

   Two findings worth recording. First, at 54 steps the boundary target is *harder* than average (`loss_cross` ≈ 4.04 for A, 2.64 for B vs ≈1.32/1.43 within), so it inflates rather than dilutes reported loss; extrapolating to `loss_cross -> 0` at convergence flips the sign (A −0.000602, B −0.001027, differential +0.000425), so the A−B differential stays bounded within ≈±0.0005 nats over the trajectory. Second, the bias does **not** simply track density — A has fewer cross targets than B but a larger bias, because the boundary transition is harder for A. Against the measured A-vs-B loss gap of 0.106 nats, the reporting differential is ≈1/360 and the optimization differential ≈1/655 of the signal, both far below seed variance. **Decision:** accept as a documented residual; do not mask. Every run logs `loss_within_segment`, `loss_cross_segment`, `n_within`, and `n_cross` so the residual is auditable per run without re-instrumenting, and `run_training(restrict_loss_to_segment=True)` reproduces the comparison. Adopting `within_segment` would be a methodological change and must be applied to every codec at once.

5. **Full-train token-rate artifact:** `obs_codecs/token_rates_train_v4.json` is locked as the budget rate source (matches §0). Regenerate via `scripts/compute_token_rates_train.py` after any tokenizer or train-corpus change.

6. **Rounding policy:** **Floor** `n_episodes` from \(T_{\mathrm{target}}\); never round-nearest. Recalculate \(T_{\mathrm{eff}} = n_{\mathrm{episodes}} \times \mathrm{avg} \times n_{\mathrm{steps}}\) and treat \(T_{\mathrm{eff}}\) as the final logged / enforced budget per codec. Guarantees no codec exceeds \(T_{\mathrm{target}}\).

7. **Multi-seed replications (plan §5, 3–5 seeds) and shuffle seeds:**  
   - **Model init seed** differs across replications (as usual).  
   - **Data reshuffle seed also differs per replication** (derived from / paired with the replication’s model seed), so data-order variance is not locked to a single shuffle while init varies — standard decoupling of those two variance sources.  
   - **Within one replication**, the reshuffle seed is **identical across codecs** (and E-variants); only episode-presentation count / \(T_{\mathrm{eff}}\) differs.  
   - Scaling \(T_{\mathrm{target}}\) for longer pilots (if any) is a constant factor shared across codecs and replications; re-apply floor afterward.

8. **Numeric \(L\) (locked):** \(L = 1024\) for all codecs. Packer implements document masking (§4.4), `<bos>`/`<eos>` at episode boundaries, and explicit `segment_ids` as mask source. See `model/README.md` Decision 1.

9. **Pilot budget profiles (locked):** Item 7's sanctioned "constant factor shared across codecs and replications, re-apply floor afterward" is instantiated as three named profiles. Each is described by a single number, `pool_episodes`, which is both the info-matched episode count and the anchor for \(T_{\mathrm{target}} = \mathrm{pool\_episodes} \times n_{\mathrm{steps}} \times \mathrm{avg}_A\); every codec's budget is then re-derived from the §0 formula with floor re-applied. `train/config.py` computes all three from that one formula (no per-tier literals), and a drift test asserts `full_v0` still equals the §1/§2 tables.

   | `tier0` | 200 | 433 752 | 0.004 | plumbing only |
   | `tier1` | 2 000 | 4 337 520 | 0.04 | plumbing only |
   | `full_v0` | 50 000 | 108 438 000 | 1.0 | scientific |

   **Compute-matched \(n_{\mathrm{episodes}}\) / \(T_{\mathrm{eff}}\) per profile** (E-variants inherit B):

   | Profile | A | B (+E) | C | D |
   |---------|---|--------|---|---|

   | `tier1` | 2 000 / 4 337 520.00 | 3 150 / 4 336 416.00 | 2 933 / 4 337 203.08 | 2 614 / 4 335 998.64 |
   | `full_v0` | 50 000 / 108 438 000.00 | 78 770 / 108 437 932.80 | 73 330 / 108 437 470.80 | 65 372 / 108 436 458.72 |

   Info-matched at a pilot tier means "the same pool size as this tier", i.e. `pool_episodes` unique episodes for every codec — not the production 50 000. Pilot tiers truncate the encoded pool deterministically (first `pool_episodes` rows), which preserves the passes-over-pool ratio across tiers and still exercises reshuffle-per-epoch.

   **Tier 0 results are for plumbing validation only and cannot be interpreted in any specific direction — the sample size (200 episodes) is far below any statistical threshold.** With 200 episodes × 30 steps = 6 000 observations spread over 4 causal regimes, a tier-0 cell sees roughly 50 episodes per regime, and the truncated pool's regime proportions drift measurably from the full corpus. ## 5. Methodology note

This draft **does not** change the experiment: it only instantiates §5 using locked `regex_v4` full-train rates. Codec definitions, info-equality, and the information contract are untouched. The locked reshuffle-per-epoch policy is an interpretation of compute-matched under a finite train pool, not a change to codec surfaces or splits. The locked fixed-context + **document-masked** packing policy is an architecture constraint required for (i) the token-update ≈ FLOPs reading of compute-matched and (ii) per-episode causal isolation under packing; it is part of the matching contract, not an afterthought for `model/`.
